# 디토체스 멀티

## 전투 기록·현재 체력/마나 (2026-09-17)

디지몬 솔로와 온라인에 피해·받음·회복·보호 탭을 연결했습니다. 피해 탭은 실제 체력에 들어간 기본 공격(주황)과 스킬(보라)을 나누고, 받은 피해는 체력 감소와 보호막 흡수를 구분합니다. 회복은 초과 회복을 제외하며 보호는 실제 생성된 보호막입니다.

전투 중 유닛을 선택하면 현재 체력·마나·보호막과 기절/시전/전투 불능 상태를 봅니다. 온라인 오른쪽의 `전투 기록 보기` / `유닛 정보 · 시너지 보기`로 전환합니다. 온라인 전투 기록은 현재 재생 시점까지만 표시합니다. 완료된 라운드는 서버 방에 별도로 남겨 다음 준비 단계와 재접속 시에도 확인합니다. 서버를 재시작하면 진행 중인 방과 기록은 초기화됩니다.

솔로의 지난 전투 유닛은 별도 복사본으로 보관합니다. 다음 준비 단계에서 장비·성급·배치를 바꿔도 지난 기록이 바뀌지 않으며, 기록 행을 누르면 당시 체력과 능력치를 확인합니다. `Play_Preview.bat`와 온라인 서버를 최신 버전으로 실행하세요.

검증: 서버 테스트 65개, 이동/타이밍 894개, C#/서버 계산 비교 1,458개, 솔로 실행 645개, 온라인 실행 57개 통과. 새 화면은 `ArenaCaptures/16-live-damage.png`, `17-damage-received.png`, `18-last-combat-unit.png`와 `OnlineCaptures/09-live-report.png`, `10-live-vitals.png`, `11-last-report.png`에 있습니다. 캡처 폴더는 `Builds/PortablePreview` 아래입니다.

## 배치 사거리·대상 선택·장비 미리보기 (2026-09-17)

- 유닛을 선택하면 기본 공격 범위를 하늘색 육각 칸으로 표시합니다. 준비 중 이동할 칸에 마우스를 올리면 그 위치의 범위를, 전투 중에는 선택 유닛의 현재 위치 기준 범위를 봅니다. 기존 표시용 원형 거리를 실제 공격 판정과 같은 육각 거리로 교체했습니다.
- 살아 있는 현재 대상이 사거리 안이면 유지합니다. 대상이 범위 밖으로 나갔을 때 공격 가능한 다른 적이 있으면 전환하고, 아무도 범위 안에 없으면 현재 추격을 유지합니다. 처음 고를 때는 육각 거리가 가장 가까운 적을 고릅니다. 솔로/온라인 모두 적용합니다.
- 장비를 선택하고 아군에게 마우스를 올리면 오른쪽에 장착 전후 공격력·주문력·체력·방어력·마법 저항·공속·시작 마나·스킬 피해를 표시합니다. 자동 합성과 추출기 회수, 슬롯 부족도 미리 확인합니다. 전장 시너지는 전장 유닛에만 포함합니다.

`Play_Preview.bat`로 최신 미리보기를 실행합니다. 온라인 대상 선택 변경은 서버 재시작도 필요합니다. 화면 예시는 `Builds/PortablePreview/ArenaCaptures/13-melee-range.png`, `14-ranged-range.png`, `15-equipment-preview.png`, `OnlineCaptures/08-craft-preview.png`입니다. 아래 항목은 각 이전 패치 시점의 기록입니다.

검증: 서버 테스트 59개, 이동/타이밍 894개, C#/서버 계산 비교 1,458개, 솔로 실행 632개, 온라인 실행 51개 통과. 실제 장착/서버 합성 결과와 미리보기 수치를 비교했으며 두 실행 로그에 예외가 없었습니다.

## 공격력·주문력 / 스킬 아이콘 / 사거리 (2026-09-17)

30종과 크립 4종을 공격·마법·혼합 딜러로 배정했습니다. 기본 공격은 공격력 100%의 물리 피해, 스킬은 각 성급의 공격력/주문력 계수로 계산합니다. 주문력은 기본 100에 장비·시너지를 더하며 기존 스킬 피해 증가율은 주문력으로 전환했습니다. 물리/마법 피해는 방어력/마법저항력으로 각각 감소합니다.

기본 공격 사거리는 무장과 공격 방식을 참고해 1~5칸으로 나눴습니다. 전장의 실제 육각 거리로 접근과 공격을 판정합니다. 스킬 아이콘을 **우클릭**하면 현재 능력치, 피해 유형, 성급별 계수와 계산 피해량을 볼 수 있습니다. 솔로/온라인 유닛 정보와 로비 도감에 적용했습니다.

전체 배정과 수치는 [COMBAT_STATS_AND_SKILLS.md](COMBAT_STATS_AND_SKILLS.md)에 있습니다. 솔로/온라인 기본 전투 능력치도 같은 JSON에서 읽으므로 서버와 미리보기를 함께 최신 버전으로 실행하세요.

검증: 서버 53개, C# 이동/타이밍 894개 및 서버↔C# 계산 비교 1,458개, 실제 솔로 실행 605개, 온라인 실행 50개 통과. 화면은 `ArenaCaptures/10-skill-magic.png`, `11-skill-hybrid.png`, `12-skill-icons.png`, `OnlineCaptures/07-skill-detail.png`에 있습니다. 아래 항목의 검증 수치는 해당 이전 패치 시점 기록입니다.

## 온라인 장비 업데이트 (2026-09-17)

일반/랭크에서도 장비 보관함, 합성·장착·회수, 유닛 장비 표시와 조합 가이드를 사용할 수 있습니다. 서버를 재시작하고 최신 `Play_Preview.bat`로 접속하세요.

- 시작 시 기본 재료 4종과 데이터 추출기 1개. 다음 라운드마다 양쪽에 같은 재료 1개를 지급하며 3/6/9라운드에는 추출기를 추가합니다.
- 재료 두 개를 차례로 클릭하면 보관함에서 합성, 장비 선택 후 아군 클릭은 장착/자동 합성입니다. 우클릭이나 `조합표` 버튼으로 상세 정보를 봅니다.
- 유닛 판매 시 장비 반환. 별 합성은 먼저 배치된 유닛부터 장비 2개를 유지하고 나머지를 보관함으로 돌려줍니다.
- 준비 완료 후와 전투 중에는 변경할 수 없습니다. 서버가 장비 소유권·슬롯·조합을 확인하며 오래된 목록으로 보낸 요청은 소모 없이 거절합니다.
- 매칭 전 `null` 방 정보를 실제 플레이어가 빈 객체로 읽어 오류를 내는 문제도 수정했습니다.

서버 테스트 44개 및 실제 Unity 플레이어↔임시 HTTP 서버의 장비/전투 흐름 40개 검사를 통과했습니다. 검증 스크립트는 `python Tools/validate_online.py`, 화면은 `Builds/PortablePreview/OnlineCaptures`, 로그는 `OnlineEquipmentSmoke.log`에 있습니다. 두 번째 참가자는 HTTP 테스트 클라이언트이며 두 PC의 실제 입력/네트워크 환경 검증은 별도입니다.

기존 `../DittochesUnity`를 보존하고 별도로 만든 Unity `6000.6.0f1` 프로젝트입니다.
Unity 로비에서 **솔로 플레이 / 일반 모드 / 랭크 모드**를 선택합니다.

## Unity에서 열기

1. Unity Hub → Add → 이 `DittochesMulti` 폴더를 선택합니다.
2. Unity 6000.6.0f1로 열고 패키지 및 이미지 임포트를 기다립니다.
3. `Assets/Scenes/Bootstrap.unity`를 열고 Play를 누릅니다. 멀티 로비는 코드에서 자동 생성됩니다.
4. 솔로 입장은 서버가 필요 없습니다. 기존 난이도·전설이 선택 화면으로 이동합니다.
5. 솔로 로비의 **멀티 모드 선택으로** 버튼으로 돌아올 수 있습니다.

솔로 저장 키와 앱 ID를 기존 프로젝트와 분리했습니다. 기존 프로젝트 파일을 수정하지 않았습니다.
솔로 진행 상황은 전장, 대기석, 상점, 장비 보관함과 전리품을 포함해 자동 저장되며 다음 실행 때 재개됩니다.

30종 플레이어 유닛과 4종 크립의 기술 정의를 `Assets/Resources/DigimonSkills.json`에서 공유합니다. 발사 준비와 명중을 분리하고, 연속 발사·범위·기절과 온라인 스킬 이벤트를 연결했습니다. 기술 JSON은 서버 배포 시에도 같은 상대 경로로 포함해야 합니다.

현재 3D 모델 제작은 집 PC 작업으로 보류했습니다. 일반 플레이는 기존 캐릭터 이미지를 사용하며 아구몬 3D 시험본은 별도 미리보기에서만 활성화됩니다. 실행과 인수인계는 [HOME_HANDOFF.md](HOME_HANDOFF.md)를 참고하세요.

Unity Editor가 없는 이 PC에서는 `Play_Preview.bat`로 기존 Mono 플레이어에 현재 코드를 적용한 시험 실행을 할 수 있습니다. 정식 Unity 빌드는 아니며 미리보기용 대체 셰이더를 사용합니다.


## 두 사용자로 테스트

**같은 PC:** Unity 메뉴 **Dittoches Multi → Build Windows Client**로 Windows 클라이언트를 만듭니다.
Editor Play 하나와 `Builds/Windows/DittochesMulti.exe` 하나를 실행합니다. Editor와 실행 파일은 별도 게스트 계정을 사용합니다.
실행 파일 두 개로 테스트하려면 다음처럼 프로필을 다르게 실행합니다.

```powershell
.\Builds\Windows\DittochesMulti.exe --profile playerA
.\Builds\Windows\DittochesMulti.exe --profile playerB
```

두 클라이언트에서 같은 서버 주소에 접속한 뒤 둘 다 **일반** 또는 둘 다 **랭크**를 선택합니다.
같은 계정/프로필은 자기 자신과 매칭되지 않습니다. 일반과 랭크 대기열은 서로 만나지 않습니다.

**같은 공유기의 다른 PC / Android:** 서버 PC에서 아래처럼 실행합니다.

```powershell
.\start-server.ps1 -ListenAddress 0.0.0.0
```

서버 PC의 `ipconfig`에서 LAN IPv4 주소를 확인하고, 양쪽 로비에 예를 들어 `http://192.168.0.10:7777`을 입력합니다.
서버 PC의 방화벽에서 신뢰하는 사설 네트워크의 TCP 7777 연결을 허용해야 합니다.
다른 기기에서 `127.0.0.1`을 입력하면 그 기기 자신에게 접속하므로 서버 PC 주소를 사용해야 합니다.

**인터넷의 다른 사용자:** Python 서버를 지속 실행할 공용 서버가 필요합니다.
현재 이 폴더 생성만으로 공용 서버가 배포되지는 않습니다. 서버를 호스팅하고 HTTPS 역방향 프록시를 붙인 뒤 모두 같은 HTTPS 주소로 접속하세요.
기본 HTTP 허용 설정은 로컬/LAN 테스트용입니다. 공개 서비스에는 HTTPS, 정식 계정 인증, 요청 제한 및 운영 설정을 추가해야 합니다.

## 온라인 게임 규칙과 조작

- 현재 버전은 실제 사용자 **2명, 1대1** 대전입니다. AI로 빈자리를 채우지 않습니다.
- 시작 체력 100, 골드 10, 레벨 3, 코로몬 1마리. 30종 유닛과 레벨별 상점 확률을 사용합니다.
- 상점 클릭: 구매. 유닛 클릭 후 목적지 클릭: 전장/대기석 이동 또는 교환. 선택 유닛 판매 버튼으로 판매합니다.
- 리롤 2G, 경험치 +4 구매 4G. 전장 배치 수는 레벨까지, 대기석은 9칸입니다.
- 동일 유닛 3개를 모으면 별 합성, 3성 완성 유닛은 본인 상점에서 제외됩니다.
- 두 플레이어가 같은 방의 기물 재고를 공유합니다. 상대 상점과 대기석은 공개하지 않습니다.
- 준비 시간 40초. 양쪽 준비 완료 시 바로 전투. 준비 취소 후 다시 편집할 수 있습니다.
- 서버가 고정 시간 간격으로 이동·공격·체력·마나·기술을 계산하고 양쪽에 같은 전투 프레임과 발사 이벤트를 전달합니다. 클라이언트는 프레임의 실제 시각으로 재생합니다.
- 패배 피해는 `20 + 라운드 × 2`, 무승부는 양쪽 15입니다. 수입은 5G + 이자(최대 5G) + 승리 1G, 경험치 +2입니다.
- 체력이 0이 되거나 10라운드 종료 시 높은 체력이 승리합니다. 체력이 같으면 무승부입니다.
- 일반은 RP 변동 없음. 랭크는 시작 1000 RP, Elo K=32로 서버가 정산하고 SQLite에 저장합니다.
- 대기열에서 20초간 통신이 없으면 취소, 경기 중 60초간 통신이 없으면 패배합니다. 60초 이내 재접속은 진행 중인 방으로 복귀합니다.
- 경기 포기는 패배입니다. 종료 결과에서 로비로 돌아가 다시 매칭할 수 있습니다.

## 현재 범위

온라인은 별도의 간소화된 전투 규칙을 사용하는 첫 프로토타입입니다. 기존 솔로 기능 전체를 온라인으로 이식한 버전은 아닙니다.
온라인 크립·초밥집·전설이 꾸미기·8인 리그·친구 초대·채팅·MMR 범위별 매칭은 아직 없습니다.
랭크는 현재 먼저 대기한 두 사용자를 연결합니다. 게스트 계정 키는 클라이언트의 PlayerPrefs에 저장되며, 다른 컴퓨터로 자동 이전되지 않습니다.
서버 재시작 시 RP는 보존되지만 대기열과 진행 중인 방은 초기화됩니다. 다중 서버/대규모 공개 운영용 구조는 아닙니다.
